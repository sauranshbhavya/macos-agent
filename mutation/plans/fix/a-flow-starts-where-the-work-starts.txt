# SONNY-510 — a flow's start page is recorded where it lands, and the loader holds the record.
# Swift half only; no file under server/ changes on this branch.
#
# Every mutant below narrows the rule back toward what it replaced, in the direction that lets a pack
# through that the branch claims is refused — except M3, which widens a refusal and is here because
# every Google pack in the tree lands on accounts.google.com, so an allowance nobody holds is one a
# later session deletes as dead. M1 is the kickoff's "returns the check to the own-domain test alone"
# and M2 its "accepts a recorded landing whose host differs from the declared one".
#
# The samples that kill these are JSON decoded through SkillPackDecoder.decode, never values built
# downstream of it (SONNY-388), so each mutant is on the path of the tests that hold it.
#
# Round 2 (review-272) added K3, K4, K5 and D1, which are the review's own probes, and M13 to M15 for the
# three checks that round added. Round 3 (the founders' decision C) replaced the pack's own signInURL with
# a fixed list of identity hosts, re-anchored M2, M3, M13, K3 and K5 on it, and added I1 to I3 for the
# list itself: a host that forgets which sites it signs in for, a host nobody read, a host dropped.
# Round 4 (the full review) added I4, its own widening mutant, which the first version of the list's
# population test let through because that test read its expected answer out of the list, and I5, which
# narrows the sign-in-only check back to off-site landings.
#
# **What a plan of this shape cannot do**, as the review put it: every mutant here deletes or narrows a
# guard that exists, so none can find a guard that was never written.
# Review-272's F3 (the sign-in host admitted any word) and F4 (the declared URL's query was never read)
# were absent code, and only probing the rule from outside found them.
