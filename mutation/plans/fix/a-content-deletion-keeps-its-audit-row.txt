# SONNY-436 — an account wipe clears the stored response bodies inside the transaction that deletes
# the content and writes the sonny.content_deletion row, so a cancel at any point leaves either
# nothing done or all of it recorded, and the row's stored_responses is the count that transaction
# cleared. Since PR #242's review (F1, founders' decision B) the clear runs last, just before the
# row, so the account's idempotency-key rows are locked only to the commit.
#
# SERVER HALF, DATABASE SUITE. Every path below is under server/, so scripts/mutate-all runs this
# plan against `cd server && npx vitest run`, and only with DATABASE_URL set (WORKFLOW.md's weekly
# battery starts the database). Every killer below lives in a database test file and skips without
# a database, so without one every mutant here would read as a survivor nobody tested.
#
# Not run on this branch (founder-triggered batteries, 2026-09-10). The killers below are the tests
# each mutant was written against, not a measurement. What WAS measured on the branch is two whole
# trees: the five tests of content-deletion-audit.db.test.ts at ef0fd5d5, run against `git archive`
# of main at 95325331, fail the three cancel tests on `storedBodies: 0` and the waiter test on a
# replay that re-claims; run against 400d1a14, the clear-first order, they fail the waiter test
# alone, on a replay that waited. The changelog entry carries both runs.
#
# Intended killers, all in content-deletion-audit.db.test.ts unless named:
#   M1 — the three cancel tests (bodies gone after the cancel) and the waiter test "a wipe held in its
#        content phase makes neither a replay nor a metering claim on the account's key wait …"
#        (the clear has committed before the content phase, so the replay re-claims).
#   M2 — "DELETE /v1/account/content?before bounds the stored bodies it clears and records by
#        claimed_at", the only test asserting which bodies a bounded wipe takes.
#   M3 — "DELETE /v1/account/content cancelled between the units …" and the waiter test.
#   M4 — "DELETE /v1/account cancelled between the units …" alone.
#   M5 — "the closed-account sweep cancelled between the units …" alone.
#   M6 — the retry, recovery and released-wipe count assertions in the three cancel tests, the waiter
#        test and the cutoff test, and in content.db.test.ts "takes content, snapshot membership and
#        the stored idempotency responses", "takes an account whose only residue is a stored response
#        body" and "closes an account and takes its content, its lineage and its stored responses
#        with it".
#   M7 — the waiter test alone: the transaction is still whole, so every cancel test passes, and only
#        a request on the key held for the whole wipe can see the difference.
