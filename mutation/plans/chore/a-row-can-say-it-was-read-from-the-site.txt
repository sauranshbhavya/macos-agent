# SONNY-501 — a catalogue row can say its flows were read from the live site, so every pack can be
# deep. Swift half only; nothing under server/ moved on this branch.
#
# What the branch claims: a pack may be deep when its catalogue row's task_flow_docs says `deep` or
# `site`, and on nothing else, and when that row names at least one page the flows were read from.
# W1, W2 and W3 widen the first half past the two allowed values or drop it altogether; W4 reads the
# pack's depth the wrong way round; W5 drops the page condition; C1 and C2 are the wiring mutants.
#
# W5 used to be "the column's vocabulary forgets `site`", against a `taskFlowEvidence` set. That set is
# gone: review-260's F3 measured that removing `shallow` from it passed all 30 tests, because neither
# of its two uses pinned it and one read it as a loop's own population. The tally in
# theCommittedCatalogueIsTheListTheFoundersDecided refuses an unknown word by counting, so nothing
# replaced it.
#
# The expected killer of W1 to W4 is the one test, in Tests/MacAgentCoreTests/SkillPackTests.swift:
# aDeepPackNeedsDocumentedOrSiteReadFlowsAndAShallowPackSitsOnAnyRow. That is not a gap in this plan
# and it is worth saying why, because a reader will expect the 473-pack loop to be among the killers.
# It cannot be. No catalogue row says `shallow` any more — the 54 that did are the rows this branch
# moved — so everyShippedPackLoadsAndEveryOneIsARowOfTheCommittedCatalogue has nothing to refuse and
# passes exactly as warmly with the narrowing gone. The held samples are the whole guard, which is
# why they run through depthProblem rather than asserting against literals, and why the mutants aim
# at it.
#
# W2's one-line `from` block sits inside W3's three-line one, and C1 and C2 share a `from` block
# outright. Each mutant is applied to an unmutated tree, so every one of them still matches exactly
# once (`scripts/mutate <plan> --check`, at the head this plan was written at).
#
# C1 and C2 are the mutants that measure the shipped population, and they are data mutants for the
# reason SONNY-492's plan gives for its own C1: a mutant of a test's own assertion survives on every
# tree where the property holds, so it would be a survivor every week and measure nothing. C1 instead
# makes every row read as `shallow`, the way a catalogue nobody had updated would, and every deep pack
# shipped at whatever head the battery runs then sits on a row that refuses it. Expected killers:
# everyShippedPackLoadsAndEveryOneIsARowOfTheCommittedCatalogue, naming a pack, and
# theCommittedCatalogueIsTheListTheFoundersDecided on the split. It survives only if the loop over
# the shipped packs stopped consulting the check. It was also shown by hand on the branch, both
# directions, by moving one deep pack's real row: to `shallow` the suite went red naming notion, to
# `site` the same test passed (the changelog entry has both runs).
#
# C2 is the same shape for the page condition, and unlike C1 that condition has a live population to
# measure: every deep pack sits on a row naming at least one page, so emptying every row's doc_url
# cells — the state a lane's own unfilled row is in — must be caught by the same loop. A count here
# dates rather than describes, because every pack wave raises it and a rebase raised it inside this
# branch (review-260's delta pass, which caught this line claiming 95 of them); the reading is
# `grep -rl '"depth": "deep"' Sources/MacAgent/Resources/SkillPacks | wc -l` -> 103 at 1dea6c9d,
# against 370 for the `shallow` twin and 0 for a depth no pack has, which is the control. Its
# expected killer is everyShippedPackLoadsAndEveryOneIsARowOfTheCommittedCatalogue, naming a pack and
# reading "names no page its flows were read from". Shown by hand on the branch as well, on notion's
# real row, both on a `deep` row and on a `site` one.
