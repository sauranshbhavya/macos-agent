Architectural decisions / pitfalls discovered (required, write "none" if true):
- **A money act the steps never name.** The ticket warns that the money rule cannot see a flow that ends in a purchase without naming money. Render's custom-domain page says "Each custom domain you add beyond this amount costs $0.25 per month", so adding a domain can start a charge on some plans. That flow was left out rather than written without its cost. Firebase's create-a-project steps include "review and accept the Firebase terms", which is a terms acceptance inside the flow, so that flow was left out too.
- **Two steps were reworded around the rules rather than dropped:**
  - Google Cloud's project form asks for "a billing account as applicable". Naming it with Create trips the money rule as `create + account`, beside `billing`. The step names the project name and the parent resource, and leaves the billing field to the form.
  - GoDaddy's pages end with identity verification for domains under Domain Protection, by an SMS code, an authenticator app or a one-time password. Every one of those is a credential the rule refuses and Sonny must never type. The step says GoDaddy "then asks the account owner to confirm their identity".
- **Heavy machine load changes what the browser tools return, in ways that read as answers.** The load average was 74 at 00:39Z (`uptime`). Three effects showed:
  - `browser_batch` calls timed out at their ceiling and **kept executing afterwards**, so the next read could land on the page the timed-out batch had navigated to. A read labelled Render once returned Heroku's page, and was caught only because it printed its own URL.
  - `get_page_text` twice returned the previous page's text under the new page's tab. A title check on every read is what caught both.
  - Chrome dropped the whole tab group once, and the signed-out check was repeated in the new group.
- **The extension refuses screenshots on some domains, which is a different failure from a stalled renderer.** On `appstoreconnect.apple.com` it answered "Permission denied for this action on this domain". That page's sign-in form sits in a cross-origin `idmsa.apple.com` frame, which no script reads, so a screenshot was the only reader left, and it is refused.
- **The extension's output filter blocks any script result containing a query-string shape.** Page text was read with `?`, `=` and `&` replaced by spaces and URLs elided, as SONNY-510's gotchas record for URLs.
