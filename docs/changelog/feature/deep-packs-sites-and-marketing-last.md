**The start-page rule this branch was judged under** (founders, 2026-09-18, replacing both earlier halves — the sign-up-form-or-terms test and the cookie-notice ruling). A start page is acceptable when the form on it signs in an account that already exists *and* the site has a separate route for creating one. It is not acceptable when that same form is also how an account gets created, whatever words sit beside it. A terms line is evidence, not the test: it usually appears because a form creates accounts, and many products show it as boilerplate on a pure sign-in. A cookie notice is never relevant. **And two tests take two kinds of evidence.** The hazard test is **measured** signed out, because that is what can be seen. The reachability test, whether a page can reach the flow's first step, is about the signed-in product. It cannot be measured signed out, so it is **judged by reasoning**, recorded as reasoning and never written as a measurement.

**Reader notes — read these before opening a help centre.** Each one was met on this branch, and each is a way for a page that holds a flow to look as if it holds none. That is the clean-zero family `CLAUDE.md`'s Claims and evidence section describes, arriving through a browser.
- **Try every reader before calling a site unreadable.** On `help.samcart.com`, every `javascript_tool` call timed out at 45 seconds with the renderer unresponsive, and twice the whole tab group vanished after the navigation. Yet `get_page_text` on the same article, one call later, returned all of it. The same freeze hit Squarespace's help-centre home page, whose article pages loaded normally, and review-270 met it on Contentful under heavy load. `javascript_tool`, `get_page_text` and `read_page` fail on different pages, and a site is unreadable only when they agree.
- **A reader built on paragraphs and list items returns empty headings on a site that keeps its steps in plain `div`s.** Kajabi's help pages gave back "Remove filters" and "Save filters as a Segment" with nothing beneath them. Splitting the cleaned `textContent` at every block element recovered the steps. A heading with nothing under it means change readers, not that the section is empty.
- **The mirror of that one: `get_page_text` dropped Etsy's numbered steps, and the cause is a collapsed toggle.** On Etsy's help article it returned every paragraph and the sentence "To opt out of personalized advertising with an Etsy account:" with none of the six steps after it. The steps sit in `div.wt-content-toggle__body`, computed `visibility: hidden`, behind a button whose `aria-expanded` is `false`. The list's `innerText` is 0 characters against 267 for its `textContent` (measured in the fix round, 2026-09-18). So every reader built on `innerText` misses them, `get_page_text` among them, and it would miss a money path hidden there the same way. It is the same hiding place as the collapsed FAQ the neighbouring lane found. A block-splitting reader over `textContent` returned all six. **Kajabi and Etsy together mean neither reader is safe as a default**, and a page whose prose promises a list the reading does not show is the tell.
- **A control can be a custom element, so a search over `a` and `button` misses it.** Etsy's footer "Privacy settings" link is a `clg-text-link` element, visible, inside `footer`. A query over `a,button` for "privacy" found only "Privacy Policy", while a search over every element's text found it (2026-09-18). Before writing that a page lacks a control, search every element, not the tags a control usually has.
- **Only the title check catches a renamed article.** Squarespace's own link to its contributor article, `…/articles/206537287-Inviting-a-contributor`, lands on `…/206537287-Invite-a-contributor`, titled "Invite a contributor". Same article, renamed. The URL requested and the URL landed differ, and nothing else said so. This is SONNY-463's slug trap on a second help centre, reached by following the site's own link.
- **A JS string over about a thousand characters comes back truncated** in the tool's output. Return an array of lines instead, which truncates only past 100 items. And keep a `browser_batch` to one page: a long batch timed out as a whole though each action inside it completed.
