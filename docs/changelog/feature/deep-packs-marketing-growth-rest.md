Architectural decisions / pitfalls discovered (required, write "none" if true):
- **A start page must be able to take its own step 1, and a page that passes every other rule can still fail that** (review-266's F1). Semrush's flow first started at `https://www.semrush.com/position-tracking/`, the public product page the cited article itself links as "Position Tracking tool" — on-domain, no redirect, no account-creation form. It was the only one of the eleven start pages from which step 1, "Open the Position Tracking tool from the left-hand menu", **cannot be performed**, because the marketing page has no left-hand menu. This is SONNY-510 shape 4, the start page that cannot reach the flow's first step, reached not by a redirect but by choosing a page that reads as the product because it is the advertisement for it. The fix was one cell already in the catalogue: `https://www.semrush.com/login/`, re-measured signed out as an ordinary sign-in page — stays put, title "Log in – Semrush", heading "Log in", 1 password and 1 email input, "Sign up" demoted once, **0** occurrences of "agree to". **The instrument that caught it is worth separating from the one that did not.** The reviewer compared that page against `buffer.com/`, which this branch rejected, on the same three measures — Buffer 1 email input, "agree to" twice, 3 sign-up calls to action; Semrush 0, 0, 3 — so the two are *not* the same page, and the Buffer rejection was better founded than the comparison suggests. The finding rests on the step-1 mismatch alone, which no offer-shape measure can see.
- **A help centre's own index can hand you a stale slug, so following an index link is not immune to the slug trap.** SONNY-463 records the trap and says following a link from the index is the one approach immune to it, "because the index supplies the id and the slug together". Measured false here: Semrush's KB index links `/kb/1191-creating-position-tracking-campaign`, and that URL lands on `/kb/1191-track-your-rankings`, title "Track your rankings". The id is authoritative and the slug on the index was stale. **Review-266 made this sharper by counting rather than sampling**: that one index page carries **three** anchors to article 1191, two with the current slug and one stale — so a single page serves both spellings for one article, and which one a lane follows is luck. It cost nothing here because the landed page is the same article renamed, and the citation this branch ships is the landed URL. But **only the title check caught the difference**, so the rule is *no exceptions* rather than "the index is immune": following the index narrows the risk and removes nothing, and the title check stays the only uniform one.
- **A domain refusal can be transient, so retry before recording "blocked at the browser".** This group's previous session recorded eleven help centres as blocked by the extension's domain permissions. With the permissions widened, ten of twelve were reachable — and three of those (`www.semrush.com`, `app.publer.com`, `app.metricool.com`) refused a navigation once and served it on the immediate retry, in the same session, with nothing changed. A refusal read once is the clean-zero family in a browser: the wrong answer is the one that stops you working. It is also the mirror of the note that lane left, that a permission which worked is not a permission that keeps working; both directions are real, and the remedy for both is a retry.
- **There are three browser states, not two, and the third is easy to read as the second.** A domain can refuse *navigation* (`publish.buffer.com`: "Navigation to this domain is not allowed"), allow navigation and refuse *reading* (`login.buffer.com`: `read_page` → "Permission denied for reading pages on this domain", while `javascript_tool` on the same tab answered normally one call later), or serve both. A lane that folds the middle state into "blocked" loses sites it could have written.
- **`read_page` is the fallback when a page answers almost nothing, and it agreeing is itself the measurement.** Another pack lane's tip, applied to this branch's one unreadable start page: `app.metricool.com/login` returns 45 characters after script and style are stripped — "Loading, please wait... Preview not available" — and `read_page` returns the same four nodes. Four readings agree: `javascript_tool` at about 9.5 s and again after a reload at 12 s, `read_page` at 6 s, and `read_page` again after a deliberate **28-second** wait, which is the test for the shape another lane measured going from 0 anchors at four seconds to 145 at nine. Two independent readers agreeing is what turns "I could not read it" from an instrument problem into a property of the page, which is the distinction SONNY-463's Buffer correction was about. It is what makes Metricool an exclusion rather than a retry.
- **Buffer is readable, and the numbers are the same ones SONNY-463 recorded.** On the cited article `innerText` is 33 characters while `textContent` is 233,873 and carries the article's own prose. A reader built on cloned nodes with `script` and `style` stripped, reading `textContent`, got clean prose on the first attempt. There was never a shadow DOM here.
- **A start page and step 1 have to agree, and the catalogue's `sign_in_url` path is what makes that possible twice on this branch** (SONNY-510's cheap fix, applied and measured). PartnerStack is a fresh instance of shape 1: `https://dash.partnerstack.com/` signed out lands on `/handshake/signup`, heading "Join the PartnerStack Network to discover and build incredible partnerships." — account creation, reached from a bare origin, on the site's own domain, exactly Ghost's shape. `https://dash.partnerstack.com/login` lands on `/handshake/login`, heading "Sign in to PartnerStack", with Sign up a demoted link, so that is the declared start. Buffer is the same fix for a different reason: its app front door cannot be opened at all, and `https://login.buffer.com/login` lands on `auth.buffer.com`, title "Buffer - Log In", heading "Log in to Buffer", one password and one email input with "Create an account" as a link.
- **A reachable start page can be worse than an unreachable one.** With `publish.buffer.com` refused, `https://buffer.com/` was the obvious substitute and is inadmissible: one email input, three "Get started" controls and "you agree to" twice — shape 3, where nothing redirects and what is wrong is what the page offers. Checking the substitute rather than assuming it is what kept Buffer's start page honest.
- **Money sits in the neighbouring control, and once here it sat in the sentence itself** (SONNY-506, and the SONNY-508 class). Luma's create flow ends on the event management page whose sibling tabs include Registration, where ticket pricing lives; the flow never enters it. Luma's hosts page describes the Manager role as one that "can send invites, manage payment, etc." — **that clause is dropped rather than paraphrased**, because carrying the page's own sentence makes the pack refuse to load, and renaming a real capability is the Pinterest mistake. The step says what Manager and Non-Manager grant and stops there; the dropped clause is named on the ticket and on SONNY-508.
- **Which words the money rule fires on is measured, not read off the lists — and the first version of this entry got it wrong in the direction that matters** (review-266). This entry and SONNY-508 both said the refusal was `send` + `payment`. It is **`add` + `payment`**: putting Luma's sentence back verbatim and running the completeness test gives `movesMoney(field: "flows[1]", words: "add + payment")`, exit 1. `send` is on `actionVerbs` and so is `add`, but `actionVerbs.first(in:)` answers in *list* order and `add` is the first entry — and the `add` it finds is in a different step, "Hosts with the Manager role can add, remove and manage other hosts". So **removing only "send" leaves the pack refused**, measured the same way: still `add + payment`, still exit 1. That is why a wrong attribution here matters rather than being a slip: it names a one-word fix that does not work, and a later session following it would conclude the rule is broken. A flow is one unit, so any listed action verb anywhere in it meets a money object anywhere else; the object is what has to go.
- **A cited `doc_url` is a candidate, not a mandate.** Birdeye's `doc_url_2` was read in full and rejected: its steps include "Log in to your Facebook account" and an opt-in that grants an app access to every current and future Business — a sign-in and a permission grant. Birdeye's article splits into "Responding to Reviews on an Integrated Source" and "Responding to Reviews on a Non-Integrated Source", and the flow's later steps came from the first without saying so.
