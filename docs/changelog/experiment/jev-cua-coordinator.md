Behavior added:
- A two-level agent. An OpenAI coordinator (`gpt-5.6-luna` by default, the production vision planner's model, so results compare) reads a text summary of the current window — app, title, the offered controls, the visible words, never a screenshot — writes a plan of short instructions, and after each one judges continue / done / failed with a strict-JSON verdict.
- A Jev action model (TypeSafe, `jev-latest`) that picks, in one request, an operation (CLICK, TYPE_TEXT, PRESS_RETURN, PRESS_ESCAPE, SCROLL_DOWN, SCROLL_UP, WAIT, DONE, BLOCKED) and speculatively a target per targeted operation, from the indexed accessibility tree `get_window_state` returns; the executor reads only the target head the chosen operation names. Every answer is validated as jev-ultrafast validates it — offered key, full distribution summing to one, choice at the argmax — and an invalid answer executes nothing.
- One text-generation door: a small OpenAI model (`gpt-5.5` by default) writes a field's value as `{"text": string | null}`, strict-schema, and `null` types nothing.
- cua's action-selection ladder as pure code (`ladder.ts`): accessibility action in the background first; settle on `effect: "confirmed"`, on a changed fresh-snapshot fingerprint, or on the typed value appearing in the field; climb on the driver's `escalation.recommended`, or one rung on an unverifiable / no-op result with nothing moved; never climb down; a "page" recommendation maps to foreground because the page rung is not built, and the report says so. The px rung aims at the element's frame centre converted from screen-absolute to window-local screenshot pixels at the screenshot scale (Known limits page), and is skipped, not guessed, when the geometry is missing.
- A pinned driver fetch: `scripts/fetch-cua-driver.sh` downloads `cua-driver-rs-0.28.2-darwin-arm64.tar.gz` and refuses to unpack unless its SHA-256 is `818ddefa…6daa` (read from the release's `checksums.txt` on 2026-09-17 and pinned in the script, not fetched at run time), into a git-ignored folder; nothing on PATH, nothing in `/Applications`, no sudo.
- Five benchmark tasks and a JSON report per run (`runs/<task>-<time>.json`): tree SHA and dirty flag, every instruction, every decision with confidence and top alternatives, every ladder attempt with rung and `effect`, and totals for coordinator / Jev / text / driver / observe time, rungs used, exhausted ladders and truncated snapshots.

Architectural decisions / pitfalls discovered (required, write "none" if true):
- **Kickoff decisions (founder, 2026-09-17), recorded on SONNY-517:** the coordinator session builds this itself in its own worktree, as a stated one-off exception to "the coordinator never implements" — the rule protects work headed for `main`, and this branch is measured, not merged; TypeScript on Node 22; OpenAI for both LLM roles; native + browser task set; the driver fetched pinned and checksummed rather than installed by hand.
- **The coordinator sees text, not pixels, on purpose.** A task that fails because the accessibility tree was blind to something is a finding about the tree, which is the thing Sonny would depend on; `degraded_reason` and the truncation counts in the report are where that shows. A screenshot-reading coordinator is the obvious next arm and is listed as such in `FORSAURANSH.md`.
- **Safari, not Chrome, for the browser tasks.** WebKit exposes page content through the AX tree with no setup; Chrome needs cua's CDP `browser_*` route, which is a different rung and a second experiment.
- **`cua-driver mcp` cannot start from an unpacked folder on its own.** It launches `CuaDriver.app` through LaunchServices by *name*, expecting `/Applications/CuaDriver.app`, so macOS attributes the TCC grants to the app's signed identity (`com.trycua.driver`, team `YCK386LBJ7`) rather than to the spawning terminal. `open -n -g <path>/CuaDriver.app --args serve` launches the unpacked copy by path through LaunchServices, after which `mcp` proxies to it; the manual-test file has the command. Until Accessibility and Screen Recording are both granted, every tool call — `check_permissions` included — answers `permissions_pending` and nothing else; `cua-driver permissions grant` raises the dialogs and times out if nobody answers them.
- **npm 10.9.8 crashes on vitest's peer set.** `npm install` dies with `Cannot read properties of null (reading 'edgesOut')` inside arborist's `#loadPeerSet`, on vitest 4.1.11 exactly as on 5.0.1, with the runtime dependencies installing cleanly in isolation — measured in two scratch folders. `server/` never sees it because its lockfile already resolved. `.npmrc` sets `legacy-peer-deps=true`, which skips that resolver; the committed lockfile makes the result deterministic afterwards.
- **Passing a live array where a snapshot was meant.** `runTask` handed its `queue` and `history` to the coordinator and executor by reference and mutated them afterwards; two tests caught it through fakes that kept the reference. Both hand-offs copy now. Same shape as an aliasing bug in production code, caught before there was any.
- **The driver's response shapes are asserted leniently on purpose** (`types.ts`: `passthrough`, optional fields, `escalation` accepted as object or string) because they were written from `cua-driver describe <tool>` and the docs, not from a live payload — the live probe (`src/probe.ts`) is what confirms them, and it could not run before the grant. A wrong field name fails at the boundary with the tool's name in the message rather than as an `undefined` downstream.

Known limitations / deferred scope:
- Live runs not yet made: every tool call is refused with `permissions_pending` until the founder grants CuaDriver its two permissions; the five tasks, their figures and the driver-shape confirmation are owed on SONNY-517 once that lands.
- The page rung (cua's `page` / `browser_*` tools) is not built; a recommendation for it climbs to foreground and is counted.
- `get_window_state` is called with `include_screenshot: false` everywhere, so the report carries no images; recording a run is `start_recording`'s job and is not wired.
- The text helper's `visibleText` reads `tree_markdown` when present and the element labels otherwise — whether `tree_markdown` carries static text the structured `elements` array omits is one of the things the live probe answers.
