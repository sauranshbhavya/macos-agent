# Known-synthetic strings already in this repository, exempted from check-secrets.sh by exact match.
#
# Every entry is a test fixture for the LOCAL REDACTION feature, whose whole purpose is to detect
# credential-shaped text on screen before a capture is sent. Those tests cannot do their job without
# containing strings that look exactly like credentials, so the scanner matching them is correct
# behaviour, not a false positive to be tuned away.
#
# Why an exact-string baseline rather than the alternatives, each of which was considered:
#   - Skipping Tests/ by path would mean a real key pasted into any test is invisible forever.
#   - Loosening the patterns would blind the scanner to the vendor prefixes it exists to catch.
#   - An entropy heuristic fails silently in the one direction that matters.
# An exact-match baseline can only ever exempt the strings written here, and adding a real key to
# it would mean committing that key to this file in a reviewable diff -- which is self-defeating in
# the obvious way, and that is the property being bought.
#
# Adding an entry is a deliberate act and needs a reason on the line above it. The scanner reports
# entries that no longer appear in the tree so this file cannot quietly rot.
#
# Baseline taken 2026-08-21 at 4b0e338. Files are named for orientation only -- matching is by
# string, so moving a fixture between files changes nothing here.

# hyphen, so `grep -EnI "$pattern"` parsed it as options and that pattern silently never ran -- the
# scanner reported clean over a tree it had never searched for private keys. check-secrets-selftest.sh
# caught it on its first run; the fix is `grep -e`.

# Four PEM fixtures then appeared, and baselining their headers as literals was the WRONG fix: it
# would have exempted every PEM header in the tree, a real one included. The selftest caught that
# too, on the very next run. The pattern now requires key material after the header instead, so no
# baseline entry is needed for any of them -- which is why this section lists none.
